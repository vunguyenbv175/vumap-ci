## What runs here

- **Android CI** — `assembleDebug`, `testDebugUnitTest`, and `lintDebug` with JDK 17; uploads the
  debug APK as a workflow artifact.
- **Signs host tests** — compiles and runs the JDK-only rule engine, validates the synthetic signs
  fixture, runs the pack pipeline tests, and checks byte-identical `.vupack` rebuilds.
- **Snapshot integrity** — verifies every exported file against `PUBLIC_SNAPSHOT.json`.

All workflows use `permissions: contents: read`. No repository secrets are required or used. There is
no `pull_request_target`, no private-repository token, and no external deployment step.

## What is intentionally absent

The export allowlist includes only the app module, the signs feature and its test fixtures,
the Gradle wrapper/configuration, and generated CI files. It intentionally excludes:

- private git history and unreviewed branches;
- owner plans, analysis, review adjudications, and reverse-engineering notes;
- credentials, keys, tokens, environment files, local SDK configuration, and keystores;
- reports, build outputs, IDE state, and agent state;
- personal media, GPS traces, camera media, and vendor-specific data;
- data outside the reviewed allowlist, including any real regional dataset without verified public
  redistribution rights.

The synthetic fixtures and the bundled `.vupack` are **synthetic test-only** data. They are not
surveyed signs, not navigation data, and must never be used for driving or field decisions.

`feature/signs/fixtures/osm/hanoi_maxspeed_bbox_osm.json` is a compact real OpenStreetMap extract (four ways) used only
as offline road-evidence adapter test input. Its adjacent `.provenance.json` records the
Overpass query, bounding box, retrieval timestamps, and the ODbL-1.0 license with
OpenStreetMap attribution. It is not field-surveyed, not a legal speed verification, and is
never built into a synthetic navigation pack.

TPMS source is included only because the Android app module references it. It is marked
synthetic/`DEVICE_UNVERIFIED` and contains no vendor firmware, vendor APK, captured sensor frames,
camera media, or real device data. A narrow publication redaction removes private document names and
vendor reverse-engineering references from included comments/warning text; it does not change build
inputs or test behavior. `PUBLIC_SNAPSHOT.json` lists the redacted paths.
